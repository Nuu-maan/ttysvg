# ttysvg.dev

The marketing site and documentation for [ttysvg](https://github.com/Nuu-maan/ttysvg).

```bash
pnpm install
pnpm dev
```

## How it stays in sync with the crate

Three generators run on `predev` and `prebuild`, so nothing here is a copy that
can drift from the tool it documents.

| Script | Reads | Writes |
|---|---|---|
| `scripts/build-themes.mjs` | `../themes/*.toml` | `lib/themes.ts` |
| `scripts/build-hero.mjs` | `../docs/demo.svg` | `lib/hero-svg.ts` |
| `scripts/build-recordings.mjs` | `../examples/*.tape`, `../docs/examples/*.svg` | `lib/recordings.ts`, `public/demos/` |

All four outputs are gitignored. Add a theme to the crate and it appears in the
site's theme switcher on the next build, with no edit here.

`build-hero.mjs` also strips the palette declarations out of `demo.svg` and
namespaces its classes and keyframes, so the page can drive the recording's
colors through CSS variables without the SVG's own rules leaking onto the page.

## Layout

```
app/            routes, tokens in globals.css, opengraph-image.png
components/
  brand/        logo, wordmark, github mark
  demo/         the hero stage, theme switcher, recordings, tape source
  layout/       nav, footer, container, section
  sections/     one file per landing page section
  theme/        next-themes provider and toggle
  ui/           button, copy button, command block
content/docs/   the documentation, as MDX
lib/            site constants, generated data, fumadocs source
scripts/        the three generators above
```

## The OG image

Generated by ttysvg itself, not by a render service:

```bash
ttysvg render capture.json --png app/opengraph-image.png --png-at 11s --scale 2 --advance 7.7 --window --title ttysvg
```
